# Deploy: backend on Render, frontend on Vercel

The backend (API, WhatsApp bot, workers, PostgreSQL, Redis) runs on Render from `render.yaml`. The staff dashboard runs on Vercel and forwards `/api/*` to Render, so login cookies stay on the Vercel domain.

## 1. Backend on Render

1. Render dashboard → **New** → **Blueprint** → connect GitHub → choose `hsndevops2026/New-CRM-Travel`, branch `main`.
2. Render lists what it will create: `travel-crm-api` (web service), `travel-crm-db` (PostgreSQL) and `travel-crm-redis` (Key Value). Keep the plans or change them; the web service must be a paid instance, because the bot and workers stop on a free one.
3. Fill in the values Render asks for:

| Variable | Value |
|---|---|
| `INITIAL_ADMIN_EMAIL` | The first admin's email |
| `INITIAL_ADMIN_PASSWORD_MIN_12_CHARS` | Their password, at least 12 characters. Change it after the first login. |
| `OPENAI_API_KEY` | OpenAI key |
| `WASENDER_API_KEY` | Wasender key for a **test** WhatsApp number |
| `FRONTEND_URL` | The Vercel address, e.g. `https://new-crm-travel.vercel.app` (fill in after step 2, then redeploy) |
| `CORS_ORIGINS` | Same Vercel address |
| `WEBCHAT_ALLOWED_ORIGINS` | The landing page and booking site addresses, comma separated |

`JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` and `WASENDER_WEBHOOK_SECRET` are generated by Render automatically.

4. **Apply**. When the deploy is live, open `https://travel-crm-api.onrender.com/readyz`. It should show `"postgres":true,"redis":true`.

If Render gave the service a different address (for example with a suffix because the name was taken), put that address in `frontend/vercel.json`.

Optional keys for hotel and flight sources (`RAPIDAPI_KEY`, `SERPAPI_KEY`, Hotelbeds, Cloudinary, SMTP) are listed in `backend/.env.example`. Add them under the service's **Environment** tab when needed.

## 2. Frontend on Vercel

1. Vercel → **Add New** → **Project** → import `hsndevops2026/New-CRM-Travel`.
2. **Root Directory:** `frontend`. Framework: Vite (detected).
3. Leave `VITE_API_URL` empty. `frontend/vercel.json` forwards `/api/*` to Render.
4. **Deploy**, then copy the Vercel address into `FRONTEND_URL` and `CORS_ORIGINS` on Render and redeploy the backend.

Every merge to `main` redeploys both automatically.

## 3. WhatsApp webhook (test number)

In Wasender, set the webhook URL to:

```
https://travel-crm-api.onrender.com/webhook/whatsapp
```

and the webhook secret to the `WASENDER_WEBHOOK_SECRET` value Render generated (Render → `travel-crm-api` → Environment → reveal).

## 4. Website chat

On the landing page and booking site:

```html
<script src="https://travel-crm-api.onrender.com/webchat.js" data-lang="ar" defer></script>
```

## Notes

- The backend refuses to start in production without the generated secrets; this is intentional.
- Redis only holds queues. Back up PostgreSQL from Render's database page (Render keeps daily backups on paid plans).
